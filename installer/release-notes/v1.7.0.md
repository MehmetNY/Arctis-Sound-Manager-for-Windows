# Arctis Sound Manager for Windows 1.7.0 - no virtual cable, no third-party driver

**Windows' sound panel now shows your headset once.** ASM no longer installs, uses or shows VB-CABLE ("CABLE Input", "CABLE Output", "CABLE In 16ch").

### What changed
- **The processed microphone is the headset's own microphone.** ASM adds a small audio effect (`asm_micfx.dll`, an audio processing object — the mechanism sound-card drivers use for their enhancements) to the Arctis microphone. Discord, OBS, Teams, games… keep choosing "Arctis Nova Pro Wireless" as the microphone and receive the processed voice (noise cancelling, noise reduction, gate, compressor, equaliser), all of them at the same time. Any doubt — engine not running, a crash of the audio service, an unknown format — and the voice passes through unchanged.
- **The earlier VB-CABLE is removed by the installer** (only the one ASM 1.6 put there; a VB-CABLE you installed yourself is never touched; `/KEEPCABLE=1` keeps it too).
- **The uninstaller gives Windows back as it found it**: effect detached, the audio-protection setting restored, scheduled tasks removed.
- The output side is unchanged: per-application audio without any driver.

### Good to know (honest limits)
- The effect reaches programs that record in Windows' *shared mode* (nearly everything). A program that opens the microphone in *exclusive mode* gets the raw voice. 48 kHz, one or two channels, 64-bit Windows.
- To let the effect load, setup switches off Windows' *protection of the audio engine for unsigned effects* (`DisableProtectedAudioDG`, the same setting Equalizer APO uses) and restarts the Windows audio service once. The uninstaller puts the setting back.
- This has been verified on real Windows in CI with a stand-in microphone (two recording programs at once, the real ASM engine and RNNoise, install and uninstall) — **not yet on a real Arctis Nova Pro Wireless**. Please report what you see.
- The installer is not code-signed: SmartScreen says "unknown publisher" — *More info → Run anyway*.

See `docs/windows.md` and `CHANGELOG.md` for details.
